Runtime addon scope:
- Observes local device initiation/completion and player lifecycle; does not wrap
  gameplay or change quests, save state, network sync, pause or time dilation.
- Reads fixed settings.json/clips.json; explicit settings controls/API save only
  this mod's settings. Explicit Reload sound selections can write a bounded
  audio-inbox/pending-import.json plan; it cannot register or execute new audio.
- Uses Audioware local playback; stop/resume targets only the retained own event.
  Event IDs, filename inputs, pool size, duration and user settings are validated.
- No network client, telemetry, credentials/browser access, OS command execution,
  runtime native DLL loader, dynamic code evaluation, updater, capture, registry
  changes, scheduled task, service or OS startup registration was found in Lua.
  os.time seeds its private shuffle/cooldown; it is not a process-launch call.

Optional installed tools are explicitly different from the Lua addon:
- Manage-Audio.cmd starts the readable PowerShell manager only on double-click.
  It uses NoProfile/STA, hides its console while showing Forms, and applies
  ExecutionPolicy Bypass only to that child process; it does not persist a policy
  change, request elevation, alter antivirus or create an exclusion.
- Manage-Audio.ps1 loads Windows Forms/Drawing, walks parent directories to find
  the game, opens Explorer only on Open Inbox, and calls the adjacent reviewed
  importer in an asynchronous runspace only after the user clicks Import. No
  resident helper/autostart, downloader, microphone or screen capture is used.
- Import-BPLAudio.ps1 reads selected local recordings, checks headers/hash/size,
  preserves originals and old recordings, and writes only a checked game-root
  clips.json plus managed user bank/backups. It rejects running-game imports,
  linked targets, unexpected manifests and changed inputs. Temporary-file deletion
  is limited to its exact generated temporary path. It is not an all-files atomic
  transaction: interruption can retain audio/backups, which should be kept.

Opt-in developer tools in the Creator Kit:
- Test-Bluetooth.ps1 uses Add-Type/PInvoke to load the trusted Lua5.3 DLL explicitly
  supplied by the developer. No DLL is bundled. A Lua CLI test path is also given.
- Lua tests load this local reviewed addon/test source; importer tests execute the
  local importer against generated fixtures. The manager test extracts its reviewed
  function definitions and mocks process lookup only in isolated write fixtures.
  These test-only evaluation/native calls never run during installation/gameplay.
